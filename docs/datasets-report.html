2.1 What we do with it (preprocessing → training), all measured

Raw rows ............................. 235,795 Drop conflicting-label URLs .......... 0 (no URL had both labels) Remove duplicate URLs ................ 425 → 235,370 unique URLs Feature engineering .................. our own 16 HOST-ONLY features computed from the URL string (app/ml/url_features.py) Stratified split, seed = 42 ......... 80% train 188,296 / 20% test 47,074 (de-duplication BEFORE the split, so an identical URL can never appear in both) Train ............................... RandomForest + XGBoost ensemble Hold-out evaluation (test set only) . RF: acc 0.956 F1 0.947 ROC-AUC 0.980 XGB: acc 0.958 F1 0.950 ROC-AUC 0.984 Real-world sanity (Dataset B) ....... 38/40 correct, 0 phishing missed
Key scientific finding of the project: our first model versions used path-based features and scored ≈99.5% on the hold-out — but that was a dataset artifact (every legitimate PhiUSIIL URL is a bare domain, so “has a path” nearly predicted the label). Real-world URLs broke it. Version 3 removed those features, trading ~4 accuracy points for genuine generalisation. This accuracy-vs-generalisation story is the honest highlight of our work.

5. Two preprocessing layers (both reproducible)

5.1 Training-time preprocessing (Dataset A → model)

Implemented in ai-service/training/train_url_models.py; every count is persisted to models/url_models.training.json (§2.1 box above).

5.2 Interactive workflow preprocessing (Dataset C → audit trail)

Implemented in ai-service/app/preprocessing/pipeline.py — a fixed order, nothing automatic; the user ticks exactly which operations run:

normalize_labels → drop_invalid_rows → convert_types → detect_conflicting_duplicates → handle_missing → remove_duplicates → dedupe_on_column → drop/select columns → validate_features (report-only)

Every run stores its exact parameters, before/after class balance, per-operation counts, warnings and the full result JSON in the PostgreSQL preprocessing_runs table — preprocessing is auditable and repeatable.

7. How data flows at prediction time (no dataset needed)

URL typed by user / browser extension → 16 host-only features computed live (same code as training) → RF + XGBoost ensemble → P(phishing) → SHAP explains the exact contributors (▲ toward phishing / ▼ toward legitimate) → fused with HTML/NLP/form-link evidence → verdict + evidence persisted in PostgreSQL

8. Honesty & provenance policies (what makes this defensible)

  • Synthetic data is flagged everywhere — is_synthetic in SQL, a badge in the UI, and a dedicated label in this document.
  • Every metric is measured and stored (hold-out + sanity + evaluation_runs); anything not measured displays NULL, never a fake number.
  • No test-set training — deduplication happens before the split; the test set is never touched during training.
  • Dataset artifacts are called out, not hidden — the v1/v2 → v3 feature change is documented with both metric sets.
  • Checksummed raw data — the PhiUSIIL zip's SHA-256 is recorded in the dataset README, training metadata and this document.
