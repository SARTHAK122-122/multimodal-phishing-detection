# PhishGuard — Chrome MV3 browser extension

Real-time browser protection for the Multimodal Phishing Detection Platform.
The extension does **no local scoring**: every verdict comes from the platform's
fusion engine via the Spring Boot API (`POST /api/scans/website`).

## What it does

| Trigger | Behaviour |
|---|---|
| Any http/https navigation completes (or you switch tabs) | Sends the URL to the backend in fast mode (`fetch: true, render: false`), paints an action badge from the verdict |
| Verdict = `PHISHING` and risk = `HIGH`/`CRITICAL` | Injects a full-screen warning overlay: reason, top evidence, risk score, "Go back" / "Continue anyway" / "View full report" |
| Popup | Shows the current tab's verdict + top evidence, force-rescan, deep scan (render + screenshot), link to the full report, backend URL and scan-mode settings |
| Backend unreachable / errored | Badge shows `err` — never "safe". The popup explains the failure verbatim |

Caching: verdicts are stored **per hostname** in `chrome.storage.session`
(10-minute TTL) so ordinary browsing does not rescan the same site on every
navigation. Dismissing the warning is remembered for the session.

Privacy: the extension reads no page content, no forms, no cookies and no
credentials. Only the visited URL is sent to your own backend for analysis.
The extension never signs in, so its scans are stored anonymously
(`user_id IS NULL`) and appear in the dashboard history as shared device
scans alongside other signed-out API runs.

## Install (unpacked)

1. Start the platform (`scripts\start-all.ps1`) so the backend answers on
   `http://localhost:8088`.
2. Open `chrome://extensions`, enable **Developer mode**.
3. **Load unpacked** → select this `browser-extension/` folder.
4. Pin "PhishGuard" to the toolbar. Click the icon to set the backend URL if
   you run it somewhere other than `http://localhost:8088`.

Icons are generated by `tools/generate_icons.py`
(`ai-service\.venv\Scripts\python.exe browser-extension\tools\generate_icons.py`).

## Files

- `manifest.json` — MV3 manifest: `storage` + `tabs` permissions, host access
  for the backend (exempts its fetches from CORS) and for sites (content script).
- `background.js` — service worker: navigation hook, scan + cache, badge
  painting, message router for the popup and content script.
- `content.js` / `content.css` — the interstitial overlay (inert otherwise).
- `popup.html` / `popup.css` / `popup.js` — verdict panel + settings.

## Design notes for the viva

- **Why the extension never scores locally:** a regex/heuristic in the client
  would be trivially bypassable and would silently diverge from the evaluated
  model. One engine → one consistent verdict, and the report page shows the
  evidence trail.
- **Why fast mode by default:** navigation-time scanning must stay snappy;
  rendering (headless Chromium + screenshot) is opt-in via "Deep scan" or the
  dashboard.
- **Why the warning is an overlay, not a hard block:** the system's job is
  informed consent, not censorship — a false positive must remain escapable,
  and the user's decision is recorded for the session so the overlay does not
  nag.
- **Why `err` instead of a colour on failure:** an unreachable backend is the
  one situation where no verdict exists; showing green would be a lie.
